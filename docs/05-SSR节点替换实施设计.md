# 05 - SSR 节点替换实施设计（水体第二步）

> 2026-10-04 起草。前置：阶段1 全绿收口（`docs/02` §14.8）、探针升质 512²→1024² 过闸。
> 依据：`docs/03` §6.1（SSR 同位置节点替换）、§7.2（水体顺位 1、SSR 第二步）、
> `docs/00` §1.1（阶段2 门槛）、`docs/02` §13.3（declared-diff 流程）+ §14.6（过闸模板）。
> 本文只做实施设计；节点证据引用 `docs/03` §6.1 与 `docs/analysis/S4-water.md`，不重复取证。

---

## 1. 目标与路线

**SSR = Screen Space Reflection（屏幕空间反射）**：用已渲染的场景色 + 深度，对反射向量做
屏幕空间 ray march，产出反射颜色；超出屏幕的部分回退到既有 cubemap 探针（501）。

**路线选择**（`docs/03` §6.1「方案二选一」）：**走「SSR 替换探针的帧内合成段」路线**——
探针升质（第一步）已过闸（512²→1024²），SSR 第二步按既定口径执行：

> **同位置节点替换——输入 321（场景色）+ 461/520（深度）、输出并回 321，正好落在现有
> 拷贝的槽位上（② 拷贝消除顺带实现）**（`docs/03:129`）

501 探针**不删**：保留为 SSR ray 出屏/未命中时的 fallback，也让 `probe=0` / `ssr=0`
两级逃生门始终能退回原版行为。

**v1 范围（本文所指）**：反射质量升级（屏幕空间反射替换 cubemap 采样段）。
**不在 v1 范围**：Hi-Z 遍历 + Temporal Denoising（`docs/00:246` 完整 SSR 远期项）、
焦散、体积吸收、SSR 输出去噪、每帧多 bounce。

## 2. 被替换节点的已测边界（证据汇总）

S4 水面帧反射链时序（ResourceId 为抓帧局部量，跨帧用槽/尺寸/格式对齐，`docs/98:43`）：

| # | 事件/段 | 内容 | 对 SSR 的意义 |
|---|---|---|---|
| 1 | 段5 `ev11495–21504` 1090 Draw | 深度预通道，写 461（1080p D24S8） | 深度来源 |
| 2 | copy `ev21505` | **461→520 深度快照** | **SSR ray march 深度输入，段16 前就绪** ✓ |
| 3 | 段7 `ev21582–38636` 1150 Draw | 主不透明，RT0=321（1080p RGBA16F）、DSV=461 | 场景色来源 |
| 4 | copy `ev39225` | **321→324 折射/反射快照** | **SSR 颜色输入（避免读写 hazard），段16 前就绪** ✓ |
| 5 | **段16 `ev39270–39502` 16 Draw** | 读 501 cube（`dcl_resource_texturecube t3`）+ 520 + 324 + 661/665，**RT0=585、DS=461**，PS 15478×1/15990×4/17352×11 | **被替换目标 = 反射颜色产生段** |
| 6 | 段17 `ev39530` 1 Draw | PS 17586 读 585 → 写 321+591 | **SSR 输出经 585 并回 321 的现成汇合点** |
| 7 | 段18 `ev39585–43994` 242 Draw | 透明/水段 MRT×3 `[321,582,336]`、读 324 折射 | 消费者（水面读反射结果） |

**设计关键事实**：SSR 的两个输入（324 色、520 深度）都是**既有快照、在段16 开始前已完成
拷贝**——Vulkan SSR pass 可以在段16 触发点拿到全部输入，无需读正被写入的 321/461。
输入输出面与 `docs/03:129` 的口径完全一致，输出 585 用段17 现成的并回逻辑，**替换边界
= 段16 一段，diff 可 declared**。

## 3. 架构硬约束（由既有实测推出）

1. **合成式呈现**：不开 VK swapchain，游戏照常 Present、我们在链内驱动 VK 渲染并合成
   （`docs/00:36`）→ SSR 必须以「游戏帧内介入 + 共享纹理回写」实现。
2. **禁止每帧同步读回**：入向（游戏纹理→VK）与出向（VK→游戏纹理）都走共享纹理 +
   fence/event 闸（`docs/00:37/49-54`，出向实测 0.40–0.83 ms/帧）。
3. **出向通路已验证、入向通路空白**：现有 PoC-B 只证到「VK 写 → D3D11 拷 backbuffer」；
   「D3D11 纹理 → VK 采样」无先例（`docs/00:307` 零拷贝共享未打勾）→ 本文最大新增面。
4. **深度跨 API 共享无既定口径**：docs 中没有「D3D11 深度共享给 VK」的先例或实测
   （共享通路仅证到 RGBA8 颜色，`docs/02:681`）→ v1 不做共享 flag，改走 CopyResource
   中转（见 D2），属新增决策项，须按 `docs/02:509` 在候选帧提案声明。
5. **帧末合成时机不够**：SSR 结果必须在段17（ev39530 并回 321）之前到位，否则透明/水段
   （段18）吃到的还是 cubemap 反射 → **必须 in-frame 拦截，Present 内合成不可用**
   （这否决了「帧末覆盖」的偷懒路线）。
6. **Draw Call Hook 尚未建立**（`docs/00:306` §5.3 标 ❌）→ 抑制段16 的 16 个 Draw
   属新增钩子面，风险单列（D3）。

## 4. 关键设计决策

### D1 拦截时机与触发判据（新增 context 槽位）

反射段边界在真机**不能用 RenderDoc 事件号**（抓帧局部量），要用绑定态特征识别。
候选拦截点（模板均抄 `installCtxProbe`/`hookedRSSetViewports`，`main.cpp` L798–845；
**槽号双证已入档**：官方 d3d11.h MIDL 声明序（与 xosh 44/45 同口径）= 33/34/44/45/47/50/53/89，
游戏 api-scan 零命中槽34 → 不挂）：

| 方案 | 拦什么 | 判据 | 侵入度 |
|---|---|---|---|
| **A（推荐 v1）** | `OMSetRenderTargets`（**context 槽33**） | 非空 RT0 恰 1 个 + 1920x1080 RGBA16F + DSV 1920x1080 D24 家族 → 反射段开始（`RT0==585`/`DS==461` 只是 S4 抓帧里的对象号，**真机只能用结构判据**） | 只读不改游戏流 |
| B | `PSSetShaderResources` / `PSSetShader` | 段17 特征（PS 身份需对象级比对，ResourceId 不可用） | 判据脆 |
| C | `Draw`/`DrawIndexed` 抑制 | 计数 16 Draw | 见 D3，v2 再上 |

**推荐 A**：触发点在段16 开始、输入（324/520）已就绪、输出可赶在段17 前拷入 585。
侦察步（Step 1）先只挂不改，验证真机上该特征可稳定识别（同帧是否出现、是否唯一）。

> **前置实测（2026-10-04，`S4-api-scan.txt` × `S4-extract-pass5.json` 全帧段表）——
> 「同帧唯一」假设不成立**，同帧有 **2 个签名完全相同的强特征段**：
>
> | 段 | 事件 | RT0 | Draw | 备注 |
> |---|---|---|---|---|
> | 段16 反射段 | 39270–39502 | 585 | **16** | 每个 Draw 前都重绑一次 = 16 次 OMSet |
> | 段19 后期前处理 | 44021 | 321 | **1** | PS 1628（`S4-water.md:93`；S5 `43684` 同款） |
>
> 二者均满足「单 RT0 + 1920x1080 RGBA16F + 1920x1080 D24S8 DSV(461)」，**只靠签名不可分**。
>
> **可用判别子**（Step 1 已在 `poc-presenter.log` 记这一行，Step 2 固化 D1 时用）——
> 「本帧该对象作为 RT0 被 `OMSetRenderTargets` 绑了几次 / 跨几个连续绑定段」。
> 数字按 `ssrReconOm` 的同口径回放全帧 `S4-api-scan.txt`（全帧共 **142 次 OMSet**）得出：
>
> | 对象 | 本帧作 RT0 绑定 | 连续绑定段 | 说明 |
> |---|---|---|---|
> | 585（反射目标） | **16** | **1** | 全帧只在段16 出现，写完即被段17 消费 |
> | 321（主 HDR） | **50** | **4** | 段7 / 段15 / 段17+18+19 / 段21（段间 RT0 没换就同段；unbind 不算换） |
>
> - **判别取「1 段 vs 4 段」**，不要取次数：次数只差 3 倍（16 vs 50），且全帧另有 339 =
>   **17 次/1 段**——比 585 还多，次数根本不唯一。
> - **该判别子只在「强特征对象集合内」有效**：339 所在段签名不是强特征，所以它只能用来在
>   2 个强特征段里二选一，不能拿「≈16 次且 1 段」去全帧海选。
> - 备选判别子 =「段内 Draw 数 16 vs 1」，但要 Draw Hook（方案 C，v1 规避）。
> - **特征B 本身也带判别力，靠的是次序**：段16 结束的下一事件就是段17 换绑，而后期前处理
>   必在场景渲染之后 ⇒ 段16 恒为帧内首个强特征段，B 每帧只触发一次 ⇒ **恒归因段16**。
>   若真机上出现更早的强特征段，上面的「1 段 vs 4 段」就是第二道保险。
>
> **Step 1 预期日志基线**：`强特征=2 distinct=2 特征A=1 特征B=1`，两个强特征对象分别报
> `16次/1段` 与 `50次/4段`；异常 = 有候选却强特征0 / 有强特征而 A+B==0 / A 或 B 单项>1 /
> 强特征>2 / distinct>2。

### D2 输入通路（颜色 324 + 深度 520 → VK）

| 方案 | 做法 | 评估 |
|---|---|---|
| **a（推荐 v1）** | 触发点上 D3D11 `CopyResource(324/520 → 我方 SHARED 纹理)` → `CreateSharedHandle` 一次、VK 每帧导入同一 VkImage → fence 后采样 | 不动游戏资源；每帧 2 次 GPU 拷贝（≈16.6MB+8.3MB 级带宽，GPU 拷贝非读回，不违约束 2）；深度中转规避「深度共享无先例」 |
| b（v2 优化） | 槽5 `CreateTexture2D` 命中 321/324/520 desc 时直接加 `SHARED_NTHANDLE` 创建 | 消除中转拷贝（与 ② 拷贝消除对齐），但改游戏纹理创建属性、需验游戏侧无感知；D2a 过闸后再切 |

VK 侧新增：`VkDescriptorSetLayout` / `VkSampler` / `vkCmdBindDescriptorSets` +
`POCB_DEV_FNS` 宏扩函数（现有宏没有这几个，`main.cpp` L1475–1488）；深度 VkImage 视图
格式与 D24 兼容性在 Step 2 探测（不兼容则退 D32 支持的采样路径或转 R32）。

### D3 输出回写与段16 的 16 个 Draw（两个子方案）

| 方案 | 流程 | 优点 | 缺点 |
|---|---|---|---|
| **a（推荐 v1）**：覆盖式 | 段16 照常跑（cubemap 结果落 585）→ 在段17 入口（A 拦截点的「段16 结束/段17 开始」）Vulkan 跑 SSR → 共享出向拷入 585 → 放行段17 | **不改游戏 Draw 流**：SSR 失败时 cubemap 结果天然兜底，`ssr=0` 语义最干净；不需要 Draw Hook（约束 6 规避） | 16 Draw 白跑（GPU 成本，cubemap 采样便宜）；触发点需要第二个拦截信号（段16 结束） |
| b：抑制式 | 段16 第一个 Draw 被拦 → 先跑 SSR 拷入 585 → 吞掉 16 Draw | 省 16 Draw | 需新增 Draw Hook + 段内计数；抑制失败=反射全丢，风险高 |

**推荐 a**：最小侵入优先，v1 验通路；若帧时测量显示 16 Draw 成为瓶颈再上 b。
a 的段16 结束信号（Step 1 侦察两种特征哪个在真机稳定，二选一固化）：
- **特征A**：`ClearRenderTargetView` 发生在**强特征通道进行期间**。S4 api-scan 实测
  ev39511 清的是 `view592` = **纹理 591**（段17 的 RT1，R10G10B10A2）—— **585 整帧从不被清**；
  旧稿 `S4-water.md:114` 的「585 用后清」取自绑定态 `bound_targets()`，非清屏目标（该文件
  §Clear 方法论行本已警告过此坑），已修正。该 clear 发生时 585 仍是绑定 RT0，**信号本身仍成立**，
  但判据必须取「清在强特征期间」而非「清 585」，否则永不触发。
- **特征B**：强特征后首次 `OMSetRenderTargets` 换绑到别的 RT0（段16 → 段17 ev39512 的 321+591）。

**同步（关键成本项）**：in-frame 触发 VK 计算须等 GPU 走到该点——v1 用「事件闸 +
`vkWaitForFences`」阻塞等待（沿用 PoC-B `copyQ` 闸模板，`main.cpp` L2446–2464），
**帧时代价单列测量**；若超门槛，v2 换多缓冲（帧 N 算帧 N-1 的 SSR，牺牲一帧时效换不阻塞）。

### D4 SSR shader（v1 算法）

- 输入：324（场景色，经共享图采样）+ 520（深度快照）+ 常量（相机逆矩阵——来源见风险 R4）
  + 501 探针（fallback，同样 CopyResource 中转一个 1024² cube 亦可，或 v1 先用「屏幕边缘
  颜色延展」糊弄 fallback，探针采样推迟到 v2）
- 输出：RGBA16F → 共享图 → `CopySubresourceRegion` 进 585
- 步进：线性 ray march（固定步数 + 二分收紧），**不做 Hi-Z、不做时域去噪**（范围外）
- 判据：ray 命中 → 采 324；出屏/未命中 → fallback
- 水面法线扰动输入不在 v1（原版扰动在段16 的 17352 内做，我们替换后先用平面法线出图）

### D5 配置与逃生门

- 新增 `ssr=0/1`（`iniFlag` 模板，`main.cpp` L495–519），**默认 0（未过闸前）**，过闸后改默认 1；
- `ssr.debug=N`：每 N 帧打触发/耗时（节流口径抄 `n%256`）；
- 挂载受 `vulkan` 总闸 + `probe`（探针 fallback 依赖）联立把关，`ssr=0` 时零新增拦截。

## 6. 风险与降级

| # | 风险 | 应对 |
|---|---|---|
| R1 | 真机反射段特征不可识别/不唯一（事件号不可跨帧用） | Step 1 侦察先行；**已实测同帧有 2 个同签名强特征段（D1 前置实测）→ 必须加「本帧 RT0 绑定次数/连续段数」判别子**（次数不唯一，339 比 585 还多）；备选特征 = 强特征期间清（ev39511，真目标 591 而非 585）与 PS 身份比对 |
| R2 | 深度 520 共享/采样格式 VK 不支持 | v1 CopyResource 中转 + D32 视图探测；失败退「仅颜色 SSR + 屏幕边缘 fallback」 |
| R3 | in-frame fence 等待帧时超门槛（5%） | 多缓冲（帧 N 算 N-1）；仍超 → 按 `docs/00:97` 降级判据连续两次不过则回退方案A |
| R4 | 相机矩阵（SSR 反射向量必需）D3D11 侧拿不到 | 候选：per-frame CB 反查（pass 已测 CB 布局）、或从深度+投影反推；Step 3 前定 |
| R5 | 覆盖式时序：SSR 拷入 585 与游戏对该纹理的写竞争 | 事件闸沿用 PoC-B 模板；侦察步确认 585 在段17 前无游戏侧写 |
| R6 | 观感无自动判据 | 人工截图对照（同存档同机位），锚点只判结构不判观感（`docs/03:144` 同口径） |

**逃生门链**：`ssr=0`（零拦截，回 cubemap 反射）→ `probe=0`（回 512² 原版探针）→
`vulkan=0`（整机回读回 PoC 口径）→ `docs/00:97` 方案A（DXVK 路线）。

**诚实边界（新增 2 条，过闸后转正式）**：
⑥ SSR v1 未覆盖 Hi-Z/时域去噪/多 bounce，反射质量是「屏幕空间一跳」级别；
⑦ 跨 API 深度中转（CopyResource→共享→VK）的带宽与帧时代价仅在过闸实测后有数，
设计阶段无数据支撑。
