> 2026-10-04 起草。前置：阶段1 全绿收口（`docs/02` §14.8）、探针升质 512²→1024² 过闸。
> 依据：`docs/03` §6.1（SSR 同位置节点替换）、§7.2（水体顺位 1、SSR 第二步）、
> `docs/00` §1.1（阶段2 门槛）、`docs/02` §13.3（declared-diff 流程）+ §14.6（过闸模板）。

## 1. 目标与路线

**SSR = Screen Space Reflection（屏幕空间反射）**：用已渲染的场景色 + 深度，对反射向量做
屏幕空间 ray march，产出反射颜色；超出屏幕的部分回退到既有 cubemap 探针（501）。

**路线选择**（`docs/03` §6.1「方案二选一」）：**走「SSR 替换探针的帧内合成段」路线**——
探针升质（第一步）已过闸（512²→1024²），SSR 第二步按既定口径执行：

> **同位置节点替换——输入 321（场景色）+ 461/520（深度）、输出并回 321，正好落在现有
> 拷贝的槽位上（② 拷贝消除顺带实现）**（`docs/03:129`）

501 探针**不删**：保留为 SSR ray 出屏/未命中时的 fallback，也让 `probe=0` / `ssr=0`
两级逃生门始终能退回原版行为。

**v1 范围（本文所指）**：反射质量升级（屏幕空间反射替换 cubemap 采样段）。
**不在 v1 范围**：Hi-Z 遍历 + Temporal Denoising（`docs/00:246` 完整 SSR 远期项）、
焦散、体积吸收、SSR 输出去噪、每帧多 bounce。

## 3. 架构硬约束（由既有实测推出）

1. **合成式呈现**：不开 VK swapchain，游戏照常 Present、我们在链内驱动 VK 渲染并合成
   （`docs/00:36`）→ SSR 必须以「游戏帧内介入 + 共享纹理回写」实现。
2. **禁止每帧同步读回**：入向（游戏纹理→VK）与出向（VK→游戏纹理）都走共享纹理 +
   fence/event 闸（`docs/00:37/49-54`，出向实测 0.40–0.83 ms/帧）。
3. **出向通路已验证、入向通路空白**：现有 PoC-B 只证到「VK 写 → D3D11 拷 backbuffer」；
   「D3D11 纹理 → VK 采样」无先例（`docs/00:307` 零拷贝共享未打勾）→ 本文最大新增面。
4. **深度跨 API 共享无既定口径**：docs 中没有「D3D11 深度共享给 VK」的先例或实测
   （共享通路仅证到 RGBA8 颜色，`docs/02:681`）→ v1 不做共享 flag，改走 CopyResource
   中转（见 D2），属新增决策项，须按 `docs/02:509` 在候选帧提案声明。
5. **帧末合成时机不够**：SSR 结果必须在段17（ev39530 并回 321）之前到位，否则透明/水段
   （段18）吃到的还是 cubemap 反射 → **必须 in-frame 拦截，Present 内合成不可用**
   （这否决了「帧末覆盖」的偷懒路线）。
6. **Draw Call Hook 尚未建立**（`docs/00:306` §5.3 标 ❌）→ 抑制段16 的 16 个 Draw
   属新增钩子面，风险单列（D3）。

#### D2a-1 真机身份：324/520 怎么认（Step 2a 补充，v0.14.0）

**问题**：324/520/585/321 都是抓帧 `ResourceId`，跨帧不可用（R1 同一个坑）。不能拿 ID 去比对。
**解法：按"来源"认**，四条全部落进 `main.cpp`（帧间持久，帧末不复位）：

| 身份 | 真机识别规则 | 时机/依据 |
|---|---|---|
| **585** 反射目标 | 强特征集合里 **`runs==1`** 那个（Step 1 判别子） | 上一帧 Present 定 |
| **321** 主 HDR | 强特征集合里 **`runs>1`** 那个 | 同上 |
| **324** 场景色快照 | 槽47 `CopyResource` 的 **src 是 1920×1080 `RGBA16F`** 时的 dst | S4 全帧 3 条 Copy 里唯一 src 为 RGBA16F 的就是 `ev39225` 的 321→324；两条深度拷贝 src 是 D24 家族，被格式挡住 |
| **520** 深度快照 | 本帧**首条** src 是 1920×1080 D24 家族的 `CopyResource` 之 dst | `ev21505` 的 461→520；本帧第二条 `ev44057` 的 461→466 是**后期**深度，靠帧号锁 `g_ssrCopyFrame` 只取首条 |

- **前 1 帧学习、第 2 帧生效**：324 的识别不依赖 321（只看 src 格式）→ 第 1 帧就认出；
  585 要等第 1 帧 Present 的 `runs` 出来 → **哨兵最早第 2 帧开火**。
- **身份口径统一**：一律 QI `ID3D11Texture2D` 的指针值（COM 契约：同对象同 IID 必返同指针，
  与 `ssrViewDesc` 同款）⇒ OMSet 侧与 CopyResource 侧可直接比对。
- **但裸指针值不能解引用**（QI 后即 `Release`）——2b 要真调 `CopyResource`，故另持两份
  **活引用**：`g_ssrSceneRes`（324，来自 `pDst->AddRef()`）与 `g_ssrStrRes`（最近强特征对象，
  来自 `RTV->GetResource()`）。持 AddRef 也顺带保证对象不被游戏销毁。

#### D2a-3 2b 武装条件 + 静默失效防护（`c8b7e62` 补）

**（a）双身份守卫 —— 防过渡期误 arm**。原始条件只有「刚离开的强特征对象 == `g_ssrReflRt`」。
真机 v0.13.0 日志显示**菜单/加载期是 `distinct=1`**（帧 1..5 只有一个强特征段），
此时 `runs==1` 只会落到 `g_ssrReflRt` / `g_ssrMainHdr` **其中之一**：

- 若菜单对象恰 `runs==1` → `g_ssrReflRt = 菜单纹理`；再叠加「段16 缺席窗」，
  段19(321) 也可能等于它 → **哨兵把 324 写进主 HDR**，整帧被污染。

故武装条件加一条 `g_ssrMainHdr && g_ssrMainHdr != g_ssrReflRt` ——
即 **`runs==1` 与 `runs>1` 必须是两个不同对象**（正常双强特征格局已确立）：

| 场景 | 只设一个变量 → 守卫失败 → 不 arm | 324→585 arm 条件 |
|---|---|---|
| 菜单单段 `runs==1` | `g_ssrReflRt=M`，`g_ssrMainHdr` 空 | ✗ |
| 菜单单段 `runs>1` | `g_ssrMainHdr=M`，`g_ssrReflRt` 空 | ✗ |
| 游戏内正常帧 | 585(runs=1) + 321(runs≥4)，两值不同 | ✓ 第 2 帧起 |
| 段16 缺席窗 | `g_ssrReflRt` 残留 585、`g_ssrMainHdr`=321 → 守卫过，但 `g_ssrLastStr`=321≠585 | ✗（原判据兜底） |

**（b）desc 预检 —— `CopyResource` 返回 `void`，不匹配会静默失败**。
`ID3D11DeviceContext::CopyResource` **没有 HRESULT**；src/dst 的尺寸/格式/MSAA/片数
不一致时 D3D11 直接丢弃该调用，**画面无变化，但 `[2b]` 行照打** →
判读会误判成「哨兵执行了但没生效」甚至「没跑」。
故执行前用 `ssrResObj` 取两边 `D3D11_TEXTURE2D_DESC` 比对，日志行分叉：

- `[desc一致]` → 通路验通；
- `[desc不一致! 585=… 324=…]` → 直接给出两个 desc 定位差异（最可能 `BindFlags`/MSAA）。

判据落进 `docs/02` §14.11 checklist #9。

### D4 SSR shader（v1 算法）

- 输入：324（场景色，经共享图采样）+ 520（深度快照）+ 常量（相机逆矩阵——来源见风险 R4）
  + 501 探针（fallback，同样 CopyResource 中转一个 1024² cube 亦可，或 v1 先用「屏幕边缘
  颜色延展」糊弄 fallback，探针采样推迟到 v2）
- 输出：RGBA16F → 共享图 → `CopySubresourceRegion` 进 585
- 步进：线性 ray march（固定步数 + 二分收紧），**不做 Hi-Z、不做时域去噪**（范围外）
- 判据：ray 命中 → 采 324；出屏/未命中 → fallback
- 水面法线扰动输入不在 v1（原版扰动在段16 的 17352 内做，我们替换后先用平面法线出图）
