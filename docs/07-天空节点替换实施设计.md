### 1.2 天空像素 = 远平面（T1 硬事实一，`Sky-recon.md` §2）

| 场景 | 深度预通道末 | 段7 首 draw | 段7 末 draw | 上 1/3 占比 | 321 颜色中位（R/G/B） |
|---|---|---|---|---|---|
| S1 | 44463 | **44463** | **44463** | 100% | 0.378 / 0.519 / **0.619** |
| S3 | 54080 | **54080** | **54080** | 99.92% | 0.366 / 0.606 / **0.754** |
| S5 | **0** | **0** | **0** | — | — |

- **三个时点逐像素同数** ⇒ 段7 **零有效深度写入**（461 内容在段7 期间冻结），
  机器判定 `depth_frozen_during_seg7 = true`。
- 远平面像素 **100% 落在上 1/3**（S1 严格 100%；S3 99.92%，余 43 px 在 y=360 带），
  下 2/3 一块没有 ⇒ 该集合就是「没被任何几何覆盖」的区域。
- 颜色分布是天空的形状：**蓝移 + 梯度**（S1 B−G=+0.10、B−R=+0.24）= 有云的天空；
  S3 分布极窄（p10 0.734 / p90 0.770）= 正午晴空的均匀蓝。与
  `Screenshot_CITY.png` / `Screenshot_forest-godrays.png` 目视核对一致。
- **掩码阈值写死精确值**：`D24 == 0xFFFFFF`（即深度 == 1.0），**不要用 0.999 之类近似**
  （实测最「近」的非天空深度 S5 = 0.9884846 / S1 = 0.9870784，距 1.0 尚有 ~0.012 余量，
  但那是这几帧的机位；精确比大小写死更稳）。
- 461 是 `D24S8_TYPELESS`，回读 4 B/texel：**低 24 位小端 = D24、高 8 位 = stencil**
  （按 float32 解会得到 2.3e-38 的垃圾，写 VK 采样路径时别踩）。

**附带一条对 T5 直接有利**：520 是 **ev34689**（S1 口径）从 461 拷的快照，时点在深度预通道
之后、段7 之前；因为段7 不写深度，**520 与「段7 末的 461 内容」逐位相同**
⇒ 搭车游戏自己那条 `461→520` 拷贝拿到的深度**就是**段7 末的深度，
**不需要额外同步点，也不需要等到段7 结束**。

### 2.2 路线口径的修正（T1 之后）

计划 §Architecture 原写「321 是天空唯一落点」——**已被 T1 升级为更强的一条**：

> **321 在段7-end 是完整场景色（含天空），天空像素 = 深度精确等于远平面的那部分子集。**

「完整场景色」这半句是新事实（T1 实测 321 在段7 末含场景几何色与天空色），
它把路线从「我猜天空落在 321 上」变成「我已知 321 上哪些像素是天空，且判据是逐像素精确的」。
**掩码路线不需要先定位天空 draw** ⇒ T1 的否定结论对本路线无影响。

### 2.3 T1 的否定结论（天空 draw 不可分离）——**它支持本路线，不是反证**

| 已排除的判据 | S1 | S3 | S5 | 结论 |
|---|---|---|---|---|
| 绑定 + 状态签名聚类种类 | 788 draw / **560** 种 | 914 / **419** | 587 / **442** | 最大簇仅 21，**零可分性** |
| PS **零纹理 SRV** 的 draw | **0** | **0** | **0** | 最干净的判据全否 |
| `depthWrites` 区分度 | 700/788 不写 | 848/914 | 549/587 | 是**多数派共同特征**，不是少数派特征 |
| `blendEnabled` 区分度 | 26/788 开 | 18/914 | 88/587 | 不足以分出天空 |
| 「最后写入者」追踪 | ev46492 → **PS 1632 / VS 1623**，blend=true，writeMask=15，t0 = 1024² BC3 | ev30390 → **同一对 PS/VS** | 无远平面像素，无从追踪 | 指向 **alpha 混合的前景植被/栅栏**，不是天空（开混合 + 采材质 BC3 + 跨场景复用同一对 PS/VS） |

⇒ **逐 draw 识别天空这条路在当前工具能力下出局**（DXBC 无调试符号、无 Draw 堆栈、
无法对 VB 反查 NIF）。**而本路线从来就不需要它** —— 掩码 = 深度逐像素精确等于远平面，
是**像素级**判据而非 **draw 级**判据。**故默认路线不变，依据变强。**

唯一剩下的结构异常（`VS 1984`：S1 全帧 4518 draw 里只出现 4 次且恰好是段7 头 4 笔、
S5 出现 1 次也是段7 头一笔、**S3 为 0 次**）**列为待验，不作结论**（S3 顶部大片真实天空
却一次没用它）。本设计**不据此编造任何天空 draw 的 event / PS id**。

## 3. I/O 与触发谓词

### 3.1 段类（被替换节点的类型）

**段7 = 主不透明 MRT×3**（1080p 口径）：

| 资源 | 格式/尺寸 | 角色 |
|---|---|---|
| RT0 = 321 | 1920×1080 RGBA16F | **唯一场景色落点** = 我方合成目标 |
| RT1 = 349 | 1920×1080 R16G16 | 法线/材质类辅助（我方不消费） |
| RT2 = 339 或 342 | 1920×1080 RGBA8 | 遮罩类辅助（我方不消费） |
| DSV = 461 | 1920×1080 D24S8 typeless | 深度（我方经 **520 快照**间接消费） |

**RT0 资源身份必须运行时学**（321/342/339/349 都是抓帧 `ResourceId`，跨帧不可用，R2）。
学法照 `docs/05` D2a-1 的口径：**用结构化特征认，不用对象号**。

### 3.2 触发谓词字段（**六字段，VERBATIM 自 `Sky-recon.md` §4.2**）

全部是 `ssrReconOm(UINT n, ID3D11RenderTargetView* const*, ID3D11DepthStencilView*)`
（`main.cpp` L1551）**已经拿到的量**，**不需要新增 hook**：

| # | 字段 | 来源 | 用途 |
|---|---|---|---|
| 1 | `n`（非空视图数） | 函数参数 | 判 MRT×3（段7 内 = 3） |
| 2 | 每视图 RTV 的 `desc.Width` / `Height` / `Format` | `GetDesc` | 判 RT0 = 1920×1080 RGBA16F |
| 3 | 每视图 RTV 的资源指针 | `GetResource` | 记住 RT0 身份、判换绑 |
| 4 | DSV 的 `desc.Width` / `Height` / `Format` | `GetDesc` | 判 1920×1080 D24 家族 |
| 5 | DSV 的资源指针 | `GetResource` | 记深度目标（T5 搭车 461→520 要用） |
| 6 | 本帧 RT0 身份表 + 连续绑定段计数 | `main.cpp` L1592-1618 既有 `g_ssrRtN` | 段计数 / 每帧一次性旗标 |

**判定式**（自 `Sky-recon.md` §4.2 原文）：

> `段7 = (NumViews == 3) && (RT0.desc == 1920×1080 RGBA16F) && (RT1 非空) && (RT2 非空)
> && (DSV.desc == 1920×1080 D24 家族)`，其 **第一次不满足 = 段7-end**。

**本计划旧稿的错误已在此更正**：旧 sketch 把 **DSV461** 写进「段7-end 离场判据」。
实测 DSV 在段7 前后**恒为 461、desc 不变** ⇒ **它只能用于「进入段7」的确认，
不能用于「离场」的判定**；离场必须靠 `NumViews` 3→2 + RT0 资源指针换绑 + RT0 desc
RGBA16F→RGBA8 + RT2 消失这四件事（§1.3）。同理 **RT1（349）也不可用于离场判定**。

**已知误触发面**（`Sky-recon.md` §4.2）：段15（单 321 无 DS）、段19（单 321 + 461）也是
1920×1080 RGBA16F；`main.cpp` L1693 现有的候选条件靠 `nonNull != 1` 排除它们
（对段7 的 `nonNull = 3` 天然成立），但反过来**段7 之后的段18/段19 会被误当成
「再次进入强特征」** ⇒ 实现必须是：

```
段7 内命中 → 置 g_skyInSeg7 = true（每帧一次性，不复位）
g_skyInSeg7 == true 且本次 OMSet 不满足谓词 → 置 g_skySeg7EndPending = true（本帧一次性）
g_skySeg7EndPending 在 hook 的 real() 之后消费；ssrReconPresent 每帧复位两个旗标
```

⇒ **本帧恰好触发一次，帧内不会因段18 二次命中而重复触发。**

## 4. 同步与时序

### 4.1 copyQ 事件闸模板（跨 API 顺序保证）

**模板 = 既有 SSR 入向 EVENT 闸**（`v0.18.4` O-1 正式修法，已真机 PASS，`docs/02` §14.20/§14.20.1）：

| 侧 | 位置 | 做法 |
|---|---|---|
| D3D11 侧（发行） | `ssrInQueue` `main.cpp` L2538-2593 | 拷贝后 `End` 一条 `D3D11_QUERY_EVENT`（惰性创建，建不出降级为无闸并只打一次日志），再 `Flush()`（End 之后 Flush，让查询连同拷贝一起进驱动队列） |
| VK 侧（等待） | `ssrInGateWait` `vkrenderer.cpp` L3109-3157 | `GetData(..., D3D11_ASYNC_GETDATA_DONOTFLUSH)` + `Sleep(0)` 自旋，**2000 ms 超时放行**（绝不卡死帧），超时也消费掉免得下一帧等旧结果 |
| 接线位 | `pocbInject` `vkrenderer.cpp` L4629 | 排在任何读入向镜像的 VK 命令之前，一次等待同时覆盖多个消费者 |

⚠️ **行号勘误**：任务 brief 给的「main.cpp L2446-2464」是行号漂移前的位置；当前
**L2446-2464 落在 `ssrInBuild` 的 KMT/NTHANDLE 分支里**，事件闸实际在
**`ssrInQueue` L2538-2593（End/Flush）+ `ssrInGateWait` L3109-3157（等待）**。
**T3/T5/T6 按后者的实际位置对齐**，brief 的行号作废。

**为什么必须有闸**：`Flush()` 只提交不等待，**不构成跨 API 顺序保证**
（`docs/02` §14.19：12e 不一致 Flush 后仍 3/8；上 EVENT 闸后 12e **归零 0/9**）。

**已知代价（必须进 T7 帧时账）**：闸等待累计均值实测 **1.783 ms**（`v0.18.4`）→
**1.420 ms**（`v0.18.6` 回归），单次 1.5–3.3 ms，**已单列登记为 R3 观测项**。

### 4.3 超阈值预案

5% 闸的 5% ≈ **0.83 ms**（16.67 ms 预算，`docs/00` L167-168/L246-247）。
本路线每帧多两次全帧拷贝（入向 321 + 出向 321，各 1920×1080 RGBA16F ≈ 16.6 MB 级）
+ 一次 EVENT 闸 CPU 停顿，**是最可能撞闸的组合**。

| 预案 | 做法 | 可省多少 | 代价 / 限制 |
|---|---|---|---|
| **A（首选）子矩形回写** | 回写改 `CopySubresourceRegion`，区域 = **掩码包围盒**；掩码实测 100% 在上 1/3（S1/S3）⇒ 面积降到 ~1/3 | 出向带宽 ↓ ~3x | 需要在合成 pass 里顺带算掩码包围盒并写进一张 1×1 的 R32UI（或 atomic min/max buffer），由 CPU 读回 ⇒ **读回必须节流**（禁每帧同步读回，`docs/00` L109） |
| **B（兜底）降档** | `sky.preset=0`（`cloudscale=0.50`、`cloudsteps=32`、`cloudtemporal=0`、`lutscale=0.5`） | 云 pass raymarch 步数 ↓ 2x、LUT ↓ 2x | 画质降；0 档同时是性能回退档 |
| **C（兜底）关 temporal** | `sky.cloudtemporal=0` | 少一张历史缓冲 + 少一次 history 混合 | 无时域鬼影风险，但云在镜头转动时更闪 |
| **D（末选）跳过回写** | 只算不写（`skyOut` 就绪但不发 `CopyResource`） | 回到零拷贝基线 | 视觉无效果 ⇒ 等价 `sky=0`，不作降级手段 |

**为什么「多缓冲（延迟一帧）」不可行 —— 相机依赖**：
`docs/05` 的 2d 出向能走 1 帧延迟，是因为它的目标 585 是**下一帧特征B 才被段17 读**，
一帧延迟刚好对齐。**天空不是这样**：321 在**同帧**的段9 降采样就被消费，
写晚一帧 ⇒ 消费者读到的是**上一帧的天空**；而天空方向/太阳/云运动完全由**本帧相机**
决定 ⇒ 镜头一动就出现**错位一帧的天空 + 时域鬼影**。**帧间缓冲在本路线语义上不成立**
（唯一可缓冲的只有 LUT pass，因为它按太阳方向阈值低频重算 —— 但 LUT 不是最终输出）。

**降级判据沿用**（`docs/00` L175-176）：单 pass 连续两次迭代锚点与帧时目标双不过 ⇒
回退口径③（自建呈现），前置补齐「不抢 HWND」验证。
**逃生门链**：`ssr=0 → probe=0 → sky=0 → vulkan=0 → 口径③`（`sky` 一级由 T3 新增）。
