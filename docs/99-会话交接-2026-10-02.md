## 五、方法论与已知坑（五场景沉淀）

- **pass4 恒为权威轮**；pass2 抽样对"计数类"可用、**结构类必须全量**（pass2 外推 17607×10 是抽样假象，实际 ×1）。
- **ResourceId 是抓帧局部量**，跨场景对齐用 (槽, 尺寸, 格式, 哈希)；无 `GetTexture(rid)`，`GetBufferData` 超长自动截断，`rd.ResourceId(int)` 构造失败（pass3 已知限制）。
- **Clear 方位用 `rd.ActionFlags.ClearColor/ClearDepthStencil` 位**（方位可靠），但**"清屏目标"绑定态可能完全错误**（D3D11 走 RTV/DSV 句柄）→ 定案口径已脚本化：**`ctrl.GetUsage()` 反查（事件归属）+ `Descriptor.firstSlice`（slice 级）+ 像素 md5（终判）**，不再依赖 UI API Inspector（2026-10-02，docs/98 §③）。
- **after_clear 语义**：= 段前紧邻 Clear 且绑定目标与本段一致（同目标拆批的 B 批标记）。
- pass1 `rt_formats` 恒空（API bug）；pass5 v3 Clear 方位 / v4 viewport 均已完成（2026-10-02）。
- **UI 口径**：截图（photo mode，UI 隐藏）≠ 抓帧（正常 HUD），见 §二。
- 资源格式查询统一 `ctrl.GetTextures()` 全表建索引；无 PIX 标记。
- 旧教训：S1 首抓污染帧（PrintScreen 冲突 +8100 Dispatch）已作废；S5 首抓室内版作废——**勿引用**。
