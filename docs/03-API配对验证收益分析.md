## 1. 什么是"API 配对验证"，本分析要回答什么

**配对验证** = 用同一套无头提取脚本（`tools/rdc_extract.py` + `rdc_pass2~6.py`）分别跑「原版 DX11 基线 .rdc」与「Vulkan 移植帧」，对同一组结构锚点逐项比对，判定移植是否与原版同构。它是 §4.7 各现代化效果的**前置闸门**：只有配对通过（基线复现），才有资格在 Vulkan 侧替换/升级某个节点，否则无法区分"我升级的效果"与"我移植错了"。

本分析回答三个问题：

1. **配对验证本身买到什么**（§4 收益 / §5 风险）——即"先做配对"值不值；
2. **各候选效果（现为六个，含新增 §6.3 光照）各自能从配对数据里拿到多少输入**（§6.1~6.6）；
3. **据此的扩展顺序与进入门槛**（§6.7、§7）。

## 3. 配对验证的判定口径（可自动化）

配对不是"看图对感觉"，而是**同一脚本两跑 + 结构锚点比对**。锚点清单（基线侧数值已全部在档）：

| 锚点 | 基线值（DX11） | 数据来源 | 对配对的意义 |
|---|---|---|---|
| Draw / Dispatch / PSO 计数 | §2.1 表 | pass1 | 总量守恒是第一道闸 |
| 9 CS DXBC 哈希 | 逐字节相同（5 次） | `S*-post-cs-disasm.txt` | compute 侧可字节级对照 |
| CS 总线程 | 户外 18,786,750 / 室内 3,400,350 | pass4 | 线程组尺寸 = f(分辨率,效果) |
| 分段结构 | S1 37 / S2 29 / S3 38 / S4 36 / S5 42 段（Draw 全覆盖） | pass5 | pass 图结构同构 |
| Clear 计数与方位 | S1 19 / S2 12 / S3 18 / S4 18 / S5 23（含方位） | pass5 v3 + pass6 GetUsage | **目标必须用反查口径**（绑定态不可信） |
| Copy 三条 | 461→520 / 321→324 / 461→466（S2 仅前两条） | pass5 | 拷贝消除的收益基线 |
| 条件节点 | 512² cubemap 段（户外）、483 点光源槽、352/333 暗场景簇、466（户外） | pass5+pass6 | 条件化帧图开关是否复现 |
| 透明段规模 | S3≈100 / S5 122 / S2 159 / S4 242 | pass5 | 透明 renderpass 统一性验证 |
| 关键资源形态 | 501 cube-array 6×512² RGBA16F、321 RGBA16F、461 D24S8 | GetTextures | 资源系统/视图设计对照 |

**判定口径（沿用项目惯例）**：输出 JSON `errors` 数组为空 = 本轮成功；锚点全中 = 配对通过。批跑方式见 `docs/02` §10（`rdc_run.ps1 -Script rdc_pass6.py -Scene Sx -Targets/-PsWL`，五场景实测 19.6~68.2s、全部 errors=0）。

**→ 判定已脚本化（2026-10-02）**：`tools/rdc_compare.py` + `rdc_compare.ps1` 把上表落成 10 条 PASS/DIFF/SKIP 判定（id-free 签名，`-Base/-Cand/-Strict`），用法与自测见 `docs/02` §11。

**→ 锚点分级（2026-10-03 水体双帧标定 S4b/S4c，权威表见 `docs/02` §13.3）**：上表锚点实测分三级——
**A 逐帧确定**（formats / CS dispatch / CS 字节码 / clear 两档 / copy 结构 / 条件节点结构：S4、S4b、S4c 三帧全绿 → **硬门槛**）、
**F 注入指纹**（copies+1、copy.sequence 尾条 512²→1920×1080、copies_total+1 → 注入帧必须出现）、
**B 会话帧态敏感**（draws / pso / textures 计数 / 透明段规模 / 2048² 段签名：同日同机位两抓实测漂 −1016 draws → DIFF 先按 `docs/02` §12.6 看图归因，**不做单对硬门槛**）。
「锚点全绿」= A 全绿 + F 必现 + B 归因后无注入不可解释项（字面 10/10 仅同帧自比成立）。

## 4. 配对验证本身的收益（DX11→Vulkan 换 API 直接买到的东西）

1. **清屏目标从"歧义"变"显式"**：D3D11 走 RTV/DSV 句柄，OM 绑定态可以完全错误（S4 ev21520、S2 ev5507、**501 批间 Clear 绑 slice5 却清 slice1** 三类实锤）。Vulkan 里同一动作落到 `loadOp=CLEAR` / `vkCmdClearAttachments` / `vkCmdClearImage`，**目标写死在命令里**，配对时可静态读出。→ 消灭本项目最大的一类分析返工（③ 号遗留即为此而生，现已脚本化）。
2. **三条拷贝可消除 —— 但仅在整帧 Vulkan 化（口径③）下**：`321→324` 折射源、`461→520` 深度快照、`461→466` 后期深度 → Vulkan 用 input attachment + barrier 或双 framebuffer 乒乓，**省 3 次全屏/深度拷贝带宽**（1080p RGBA16F ≈ 16.6MB/张 + 深度 8.3MB/张量级）。**限定（2026-10-06 更正）：本项目当前走方向①（合成式 + 自写渲染器为主干），这 3 次拷贝拿不回来** —— 要拿须走口径③（自建呈现）或改写呈现链，见 `docs/00` §1.1.1 口径复核、`docs/05:461`；**不要把它记进方向① 的收益**。
3. **深度预通道直通**：原版预通道后**连深度清屏都没有**、主 pass 直接复用（S4/S2 同构）→ Vulkan `loadOp=LOAD` + 事件依赖是原生习语，**语义零损耗移植**，还省一次 clear。
4. **条件化帧图显式化**：5 常驻 CS + 4 户外条件 + 17518 零尺寸空跑 + 483 点光源槽（批数随光源数 1~4+）+ 352/333/43702 暗场景簇 + 466 户外拷贝 → DX11 是隐式状态冗余绑定，Vulkan 可**按帧条件挂载/跳过**（17518 类零尺寸 dispatch 显式不 submit）。
5. **管线缓存有键可用**：PSO 137~157/帧、9 CS 与 137 PSO 的着色器哈希跨场景逐位复用（`Shader hash` 已随反汇编导出）→ **以字节码/管线哈希为键的缓存**直接消掉原版式编译卡顿（S6 掉帧点的初判方向）。
6. **TYPELESS 问题消失**：R16_TYPELESS 阴影纹理在 Vulkan 无 TYPELESS → 双 view 显式管理（深度用途 D16 视图 + 兼容格式 SRV 视图），设计期就定死，不留运行期惊喜。
7. **G-Buffer/后期输入已锁定**：主场景 `D24S8+RGBA16F+R16G16+RGBA8`、透明段 MRT×3 `[RGBA16F, R8G8, RGBA16F]`、480×270 亮度金字塔与 5 级 2×2 链 → §4.3/§4.5 的格式表不必再猜。

## 5. 配对验证的风险与坑（移植与验证两侧）

| # | 风险 | 证据 | 对策（已沉淀） |
|---|---|---|---|
| R1 | **绑定态≠清屏目标** | 501 批间 Clear、S4 ev21520、S2 ev5507 | 一律 `GetUsage()` 反查 + `Descriptor.firstSlice`，禁止以 OM 绑定定案 |
| R2 | ResourceId 是抓帧局部量 | 3D 噪声纹理 S1=26005 / S3=20887 | 跨场景对齐用 (槽,尺寸,格式,哈希) |

| R4 | 抽样外推假象 | pass2 stride10 外推 17607×10 错（实际 ×1） | 结构类必须全量（pass4/5/6 权威），pass2 只用于计数 |

**结论**：R1~R8 全部有已验证的对策与脚本化路径；**风险不构成"跳过配对直接做效果"的理由**，反而说明配对 harness（§3 锚点表）必须先行。

## 6. 五个现代化效果逐项分析（§4.7）

评分口径：**证据完备度** = 该效果所需节点在五场景数据里被测清的程度；**依赖就绪** = 依赖的总体规划 §4.3~4.6 / §5.2~5.4 / §6.1 基础是否为它独占或共享前置；**风险** = 出错后能否被配对锚点捕获。（下文 §6.x 指本文小节，§4.x/§5.x/§6.1 渲染图 等未加前缀者均指总体规划）

### 6.1 水体现代化（SSR / 焦散 / 体积吸收 / 更高质反射）

- **证据完备度：最高**。反射 pass 五要素全清：资源身份（501 = cube-array 6×512²、单 mip、RGBA16F）、面级布局（A 批 slice5 / B 批 slice1）、清屏真目标（slice1）、像素存活（帧末 6 面全有内容）、消费者（PS 15478/15607/17352，`texturecube t3` 直采；S4 的 16 处读取构成独立 16-Draw 段 ev39270–39502 → 585 → 321 的反射合成链）。折射侧 `321→324` 拷贝位置精确、透明段 MRT×3 组合与规模（242，水增量 +83~142）已量化。
- **配对验证给它的收益**：SSR 是**同位置节点替换**——输入 321（场景色）+461/520（深度）、输出并回 321，正好落在现有拷贝的槽位上（② 拷贝消除顺带实现）；cubemap 探针升分辨率/提高更新频率则只动 501 的创建参数。**两者都有明确的 DX11 侧对照物**，配对锚点可直接判定"替换前后只有该段变"。
- **风险：中低**。注意方案二选一：原版是**预渲染 cubemap 探针**（非屏面平面反射），所以"SSR 替换探针"与"保留探针 + 升级质量"是两条路线，§4.6 原文的 Planar Reflection 假设已被证伪（本分析 §2.3）→ 先做哪条由 §7 门槛决定，但无论哪条，节点边界都已测清。
- **结论：第 1 位**。数据最全、节点替换边界最清晰、可 A/B 自动判定，且直接服务 S4 场景（水）这一基线。

### 6.2 天空 / 大气 / 体积云

- **证据完备度：高**。VL 链全量（471 2048²R16 + 477 256²R16 + 17605 4096×1 LUT + 17597/17600 320×192×90 3D、17607×1 → 17608×90 切片串行）、太阳方向/雾参/体素域在 per-frame CB（S1/S3/S4/S5 三组向量对照）、户外条件节点 17504/05 + 466、S3 godrays 场景在档；9 CS 逐字节同构意味着**新增大气/体积云 CS 是纯增量节点**，不扰动既有锚点。
- **配对验证给它的收益**：天空与水体**共享同一输入输出面**——cubemap 探针（501）的内容就是天空+场景，天空质量直接决定反射质量；反之雾参/太阳方向是水体着色的 CB 输入。两者的配对锚点（户外条件开关、CB 布局）高度重叠，**紧邻水体做可复用同一套判定**。
- **风险：中**。precomputed scattering 自成一体、边界清楚；体积云/新效果会加 CS 与 3D 噪声纹理（注意 R2 局部 ID）。依赖 §4.6 天空/体积雾基础（未建）。
- **结论：第 2 位**。与水体互为输入，串行紧邻收益最大。

### 6.3 光照现代化（Forward+ / Clustered，2026-10-06 新增）

- **证据完备度：★★★★☆**。输入 = 纹理（324/520/501）+ **per-frame CB**（471/477/483 语义）+ 「批数随光源数变」均已测清；落点 = `docs/00` §4.4 的 cluster 构建 CS + light list SSBO + PS 光照循环 patch。
- **配对验证给它的收益**：**shader patch 路线只替换 PS 光照循环、保留 BSE 材质输入** ⇒ 依赖 = 纹理 + per-frame CB，**2c 已验通**，**不吃几何跨 API**（几何 VB/IB 导入完全未动，那是材质格的独占风险）。
- **解决什么**：原版投影灯上限 **4**（超出即熄灭）、单表面约 **7**、光照 PS 灯位 **4** —— 上限**烤在 HLSL 字节码里，mod 解不掉**（`docs/00` §4.4 登记）；簇化后只遍历 tile 内相关灯，上限由我方簇剔除决定。落地路线已拍板走 **c**（`docs/00` §4.4，归阶段2、由我方 renderer 重写光照 pass，阴影上限风险一并前置 §4.2）。
- **风险：中**。patch 稳定性；半透明/blend 兼容；per-pixel 增量帧时（须过 5% 闸）。
- **结论：第 3 位**。放在水/天之后（与水共享 CB/纹理输入面）、**材质之前** —— 材质 PBR 化要吃的 albedo/normal/roughness/metal 正是光照改造的产物，**光照先行、材质随后衔接**，不是「材质做完了才有光照」。

### 6.4 材质现代化（PBR / POM / 更高精度 G-Buffer）

- **证据完备度：中高**。主不透明 MRT 格式组合、深度预通道（1090 depth-only + alpha-test PS 的 PS 形态）、137~157 PSO 的状态空间、透明段 MRT、14~16 类纹理格式均已量化。
- **配对验证给它的收益**：**改 G-Buffer = 改全帧结构**，这正是配对 harness 的用武之地——改完必须五个锚点全绿才允许继续。同时它是**共享基础设施**：更高精度 G-Buffer 既服务材质，也是超分（深度/法线/速度矢量输入）与 SSR（§6.1）的输入。
- **风险：中高**。牵一发动全身（PSO 数上升 → 靠 §4.5 的管线缓存）；POM 需要材质/几何侧新数据，配对只能验结构不能验观感，视觉回归要靠人工截图对照。
- **结论：第 4 位**。放在水/天/光照之后是因为它**改变结构最多、最需要前三者先把配对 harness 跑熟**；但它是超分的硬前置，必须在超分之前。

### 6.5 超分辨率（FSR 2.1 / XeSS）—— DLSS 已出局

- **证据完备度：中（够用但有缺口）**。分辨率常量 (1/1920, 1/1080) 在帧全局 CB、后期链金字塔 480×270→2×2 五级、后期深度 466、唯一命名动作 Present → 呈现链路与后期结构清楚；**缺口 = 原版无速度矢量**（无 TAA，jitter 无从谈起），4.5 TAA 必须先自建。
- **配对验证给它的收益**：超分是"叠加在末端"的效果，**对既有锚点几乎零扰动**（改的是呈现与抖动），因此配对通过后接入风险低、回退容易；且 DLSS/FSR 的 jitter+history 正好补上原版无 TAA 的稳定性短板（配对时的像素级差异反而会更小）。
- **风险：高（不在管线，在集成）**。依赖 §4.5 TAA（速度矢量）+ §4.3 G-Buffer + §5.2 Present Hook + §5.4 UI/HUD 分离（超分不该糊 UI）；需 hook 呈现链路并引第三方 SDK（GPL-3.0 边界要审）。**本机 GTX 1660 Ti @1080p 是瓶颈机 ⇒ 收益直接，但比本节原估更贵（2026-10-06 下调）**：① **DLSS 出局** —— 官方口径不支持 GTX 16 系，DLSS 5 的 3D-Guided Neural Rendering 是 RTX 50 硬件独占 ⇒ 可选项只剩 **FSR 2.1 / XeSS**；② **原版无速度矢量**（无 TAA），自建 velocity = 新增一个 pass + 新增 G-Buffer 通道，**是新增成本不是零成本**。
- **结论：第 5 位**（性能优先时的并行备选见 §6.7）。

### 6.6 帧生成（DLSS FG / AFMF）—— **本机出局，不执行**

- **证据完备度：低（前置不满足）**。UI 与场景在同一条 backbuffer 链上交织（UI 中途 ClearDS、UI Draw 14~58 波动）→ **UI/HUD 分离是硬前提且原版没有**；速度矢量依赖 TAA（§6.5）；需要总体规划 6.1 渲染图与 5.2 Present Hook 全部就位。
- **配对验证给它的收益**：配对通过 = 渲染图结构可信，帧生成才有"正确的两帧"可插；UI 分离的正确性可由"UI 段 Draw 计数与基线一致（R6 口径）"锚点守住。
- **风险：最高**。依赖链最长（渲染图 + Present Hook + 速度矢量 + UI 分离），任一缺失都是伪帧/UI 抖动；且它是**纯增量呈现层**，放最后做不拖累其它任何项。
- **结论：第 6 位（最后）—— 本机不执行（2026-10-06 标注出局）**：本机 GTX 1660 Ti 无帧生成硬件块（AFMF/FG 类），且 UI 分离硬前提在方向① 下更难做；**条目保留作规划参考，不进本机排期**。

### 6.7 顺序总表

| 顺位 | 效果 | 证据完备度 | 关键依赖 | 主要风险 | 为何在这个位置 |
|---|---|---|---|---|---|
| 1 | **水体** | ★★★★★ | 4.6 水面（节点已测清） | 方案二选一（SSR vs 探针升级） | 数据最全、替换边界最清、可自动 A/B |

> - **路径 A：shader patch**（保留 BSE 材质输入，只替换 PS 光照循环）→ 依赖 = 纹理 + CB，**2c 已通**，风险低 ✅ **建议 v1 走这条**

## 8. 一句话结论

**配对验证的收益（§4）真实且可量化——清屏显式化、三拷贝消除（**方向① 下拿不回**，见 §4 限定）、条件帧图、管线缓存——而它的风险（§5）全部已有脚本化对策；因此按"证据完备度 × 依赖就绪"排 extension 顺序为：水体 → 天空 → **光照（新增）** → 材质 → 超分 → 帧生成（本机出局），唯一例外是性能吃紧时 FSR1 可与材质并行。**
